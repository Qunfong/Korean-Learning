# Korean Learning - project guide for Claude

Static GitHub Pages site that teaches Korean grammar for the TOPIK (levels 1 to 6) to Dutch speakers.
Live: https://qunfong.github.io/Korean-Learning/ - deploys automatically from `main` (GitHub Pages, root folder, `.nojekyll`).
Sister project with the SAME code: https://github.com/Qunfong/HSK-Learning (Chinese, HSK 3 to 7-9). See "Two repos, one codebase".

The owner communicates in Dutch. All site text is Dutch; Korean only in examples and exercises.

## Audience: assume the learner knows NOTHING
The owner's explicit requirement: a learner may start without knowing Hangul.
- Always give the pronunciation (Revised Romanization) next to Korean, like pinyin on the Chinese site: in examples, dialogue, reading, vocab, word lists and order tokens (`py` fields). The "Romanisatie tonen" switch lets advanced learners hide it.
- The beginner path starts before TOPIK 1: Hangul (letters, syllable blocks, batchim, sound changes) and basic words with romanization.
- Explain every grammar term in plain Dutch the first time it appears (받침 = slotmedeklinker, etc.).

## How it works
- No framework, no bundler, no dependencies. Plain HTML + one `assets/app.js` (vanilla JS, IIFE) + one `assets/style.css`.
- All pages are generated by `python tools/build_pages.py`. Never hand-edit `*.html` or `assets/data/*.js`.
- Progress lives only in the browser (`localStorage` key `korean-learning-v1`, separate from the HSK site because both run on qunfong.github.io).

```
assets/src/<level>/NN-slug.js   one lesson per file: a JS object literal wrapped in ( )
assets/src/<level>/_words.js    level word list ({ themes: [{ name, words: [[hangul, romanization, nl]] }] })
assets/src/<level>/_level.json  { level, dir }
assets/data/<level>.js          GENERATED: all lessons of a level merged (window.HSK.<key> - the namespace is shared with the Chinese site on purpose)
assets/app.js                   all rendering: home, level, lesson, review, docs, word list/flashcards
assets/style.css                the whole design system
tools/site_config.py            site settings: V (cache version), brand, fonts/colours (SITE_HEAD), app settings (SITE_JS), levels
tools/build_pages.py            merges src -> data and writes every page (identical in both repos)
tools/validate.js               schema checker (identical in both repos)
tools/LESSON_SPEC.md            THE content spec for a lesson - read it before writing or changing lessons
```

Field names come from the Chinese site: `cn` = the Korean (Hangul) sentence, `py` = Revised Romanization of the whole sentence.

## Everyday commands
```bash
node tools/validate.js assets/src/topik2/07-nikka.js    # one lesson, full (deep) schema
node tools/validate.js assets/src/topik2/*.js           # a whole level incl. _words.js
python tools/build_pages.py                             # merge + generate pages
node tools/validate.js assets/data/*.js                 # check the merged result
python -m http.server 8792                              # preview locally (pick a free port)
```
After ANY change in `assets/`, bump `V` in `tools/site_config.py` and rebuild, otherwise browsers keep the old file for up to 10 minutes.

## Lesson content (summary - full rules in tools/LESSON_SPEC.md)
Order on the page: guess first -> the idea (problem, pattern blocks, rules, pitfall) -> examples -> nuance (look-alike endings, register, politeness) -> common mistakes -> 10 words -> dialogue -> reading text (+3 questions) -> 10-12 exercises (mc, fill, order, open) -> 3 review questions that come back later.
- Pedagogy from the Tutor and HSK Tutor skills: guess before teaching, distractors from one real learner error (wrong particle after 받침, vowel harmony, tense mixing, register), spaced review.
- Writing: Dutch, short sentences, active voice, no idioms, no praise, NO em dashes (validator enforces).
- order: tokens are 어절 (word + particle/ending), joined with ONE space; Korean word order is flexible, so list other natural orders in `alt`.
- Romanization is pronunciation-based Revised Romanization (liaison, nasalization; tensification usually not written).
- Never claim official TOPIK word-list membership or official exam items; content is AI-written and should be reviewed by a native speaker.

## Design system (why it looks like this)
Made with the `frontend-design` skill (claude-plugins-official). Brief: calm daily study, readable, clear where you are.
- Motif: the practice exercise book / 원고지 manuscript paper. Key syllable of a lesson in a practice square (`.grid-char`), progress as a row of squares, a red seal 합 (합격, passed) when a lesson is passed - the only animation.
- Colours: ink `#1c2230`, paper `#ffffff`, page `#f6f8f7`, primary blue `#2b5a8a` (Korean override of the shared green), grid line `#cddbeb`, seal red `#c0392b`.
- Type: Atkinson Hyperlegible for Dutch/UI; Noto Serif KR (Myeongjo) for Korean via `.zh` / `var(--zh)` (class name kept from the Chinese site).
- Layout and navigation identical to the HSK site: dashboard home with "Ga verder", sticky header, lesson page with sticky section nav and scroll spy.
- Deliberately avoided: gradients as decoration, identical shadowed cards, ALL-CAPS labels, "A · B" meta strings, "→" on links.

## Two repos, one codebase
`assets/app.js`, `assets/style.css`, `tools/build_pages.py`, `tools/validate.js`, `tools/LESSON_SPEC.md` are IDENTICAL in both repos. Change them in one, copy to the other, rebuild both. Site differences live only in `tools/site_config.py` (`SITE_JS`: language ko-KR, TTS voice, "romanisatie", word separator " ", storage key, seal 합; `SITE_HEAD`: fonts and blue colour tokens).

## Working on content at scale
Use parallel subagents, one per ~5 lessons, each given LESSON_SPEC.md + the reference lesson `HSK-Learning/assets/src/hsk3/01-ba.js` + one Korean lesson for conventions; one file per Write, validate every file. Then an order-question audit (natural `alt` orders only). Spot-check distractors: wrong options must be truly wrong (은/는 vs 이/가 is often both possible - let context decide).

## Testing notes
- In-app browser for function checks via JS; headless Edge (PowerShell, `--screenshot`) for visuals when the pane cannot screenshot; it does not render below ~500px wide, so test mobile with the in-app browser's mobile preset.
- Deploy check: `gh api repos/Qunfong/Korean-Learning/pages/builds/latest` until `built`, then curl the live `app.js?v=N`.
